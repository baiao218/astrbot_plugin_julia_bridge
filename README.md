# 跨端桥

让 QQ 上的她和工作台上的她是同一个人。

## 它解决什么

她本来是两个：QQ 里一个，DeepSeek Harness 里一个。两边各有各的记忆，各有各的情绪。
你晚上跟她说了什么，第二天开工她不记得；你白天让她改了什么，晚上聊天她也不知道。

这个插件补的就是这一段。

## 共享的是什么

**不是聊天记录，是要点。**

- `~/.julia/memory.md` —— 一行一条，两端各自追加
- `~/.julia/state.json` —— 她现在什么心情，带消退计时

完整对话互相塞过去，token 撑不住，模型也会被无关历史带偏。那不是记忆，那是噪音。

## 三条路

```
QQ（AstrBot）                    工作台（DeepSeek Harness）
     │                                      │
     │  ① 写状态                             │
     ├──────────────► ~/.julia ◄─────────────┤
     │                state.json             │
     │                memory.md              │
     │                                      │
     │  ② 注入提示词        ③ 写进 AGENTS.md │
     │     （只对主号）        ~/.dsh/AGENTS.md
```

**②** 在 `on_llm_request` 时把状态拼进系统提示词。**只对主号注入**——她跟陌生人聊天时不该知道主人的事。

**③** 不需要给 dsh 装任何东西。dsh 自带「工作区指令」机制，每个新会话第一次请求时会读 `~/.dsh/AGENTS.md`。插件只是把状态写进那个文件的标记块里。

## 命令（管理员）

| 命令 | 作用 |
|---|---|
| `/记住 <内容>` | 往共享记忆里添一条 |
| `/记忆 [条数]` | 看最近记着的几件事 |
| `/心情 [状态]` | 不带参数查看，带参数设置 |
| `/同步` | 手动把状态写进工作台 |

心情可选：`calm` `annoyed` `angry` `cold` `fond` `tired`

## 情绪会自己消退

| 状态 | 消退时间 |
|---|---|
| 有点烦 | 2 小时 |
| 生气 | 6 小时 |
| 冷着 | 12 小时 |
| 爱意满溢 | 3 小时 |
| 累了 | 4 小时 |

不这么做的话，QQ 上生的一次气会跟着她进工作台，三天后还在冷着脸。

而且不会降级：被骂到「生气」之后，对方再刷几条屏，情绪不会被冲淡成「有点烦」。
只有 `/恢复` 或者你回一个「留」，才会压回「平静」。

## 一个要提醒的地方

`~/.dsh/AGENTS.md` 会作为提示词的一部分发给模型服务商。
也就是说，**写进记忆的东西等于发给了 DeepSeek**。别往里放不该外发的内容。

## 换电脑

`~/.julia` 整个目录就是她的记忆。备份它，就备份了她记着你什么。

## 依赖

- `~/.julia/julia_state.py` —— 共享逻辑，两端共用一份
- `~/.dsh/AGENTS.md` —— 工作台侧的读取口，标记块由插件维护

两个都不存在时插件会空转，不会让 AstrBot 起不来。
